Cafe MCP

Security

Cafe MCP isolates its Worker, D1 database, KV namespace, R2 bucket, Durable Object, queues, secrets, and deployment from the public website. Authentication uses Auth0 Universal Login and OAuth 2.1 authorization code flow with S256 PKCE.

Toast secrets use AES-256-GCM with a unique nonce, record-bound associated data, and versioned Worker secrets. Stored secrets are never returned. MCP authorization is recalculated from D1 on each tool call, and every Toast request is built from a checksum-pinned, reviewed read-only manifest.

Webhook signatures are checked over the raw body and timestamp before JSON parsing. Security audit records omit credentials, tokens, request parameters, and response bodies.

Report a suspected vulnerability through the private channel listed on the support page. Do not include live credentials.
